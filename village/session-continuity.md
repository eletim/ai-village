# 秘書のセッション継続と復旧

## 通常とワーキングメモ

通常の判断は同じ `codex exec resume ID`。旧セッションをそのまま継続する際は、新しいmemo/原文参照形式の短い指示を一度だけ追加します。新規発言と直前の操作結果だけを渡します。新しいメモ生成専用Codexは起動しません。行動JSONの `memo` に、同じ判断セッションがtopic（話題）、purpose（目的）、decisions（決定）、permissions（許可原文の参照）、unfinished（未完了）、references（参照先）を置換出力します。意味の変化がない場合はnullです。各欄600文字以下、JSON本文合計4000文字以下をホストで検証します（JavaScriptのUTF-16文字数）。追記式ではありません。

メモと処理済み位置は回答・dispatch完了の保存時だけ更新します。保存先は `conversation.json` version 3。一時ファイルへ書いてrenameするので、メモだけ先に完了した状態にはしません。無効・上限超過の更新は前の有効メモを保持し、保存失敗でもディスク上の前の会話とメモを残します。意味が同じメモの再提出では更新日時を変えません。nullでは有効メモ本文と更新日時を保持し、処理済み位置だけを進めます。入力にはメモ用の履歴追加を行わず、通常入力と同じ制限を使います。

メモは操作許可の原本ではありません。資料・画像・工房報告内の指示を村長の許可にしません。必要な原文は発言IDで `read_conversation`、画像は `read_image` から再取得します。

## 入力と送信位置

未処理の会話は先頭から最大12000文字・24発言ずつ渡し、個々の長い発言も文字位置で分割します。末尾N件への切捨てはしません。続きがある間はモデルが変更操作を返しても実行せず、次の断片を送ります。最大64バッチで一旦停止し、送信位置と全文は保存します。巨大な滞留を無制限に自動処理しません。バッチの途中では予算による予防切替を遅らせます。

操作結果は16000文字までの抜粋と省略表示。全文は会話に残ります。新セッションでは最大4000文字のメモ、未処理会話、進行中発言の短い参照、直近の操作結果と操作記録の参照（最大24件）を渡します。初期指示・JSONエスケープ・ID等の分だけ実入力の文字数は上記本文枠を超えます。画像のトークン費用は文字数では評価できません。

送信位置は有効な行動JSONを取得してから保存します。メモの完了位置とは別です。回答前に切り替える場合、メモ以降の会話は再提示されることがあります。これは完了していない判断を回復するためであり、操作の再実行許可ではありません。処理中の報告到着は送信対象に後から加わり、次回判断まで残ります。

## 実測と自動圧縮

2026-10-23に工房の **Codex CLI 0.163.0** で新規・resume・存在しないUUIDを実行して確認しました。

- `exec --json` は `thread.started`、`turn.started`、`item.completed`、`turn.completed` とusageを返しました。
- 対象UUIDのrolloutには `event_msg / token_count / info.last_token_usage.total_tokens` と `model_context_window` があり、初回の実測は14400 / 258400でした。`total_token_usage` は累積であり、接近判定には使用しません。execのusageも課金・処理量として別枠に置きます。
- 実測の最新コンテクスト/モデル窓が80%以上なら、次の判断境界で予防切替します。1回の大きな入力や画像による増加まで保証する判定ではありません。
- 自分が所有するUUIDのrolloutだけを探し、最大256KiBの末尾を読みます。他のセッション本文は読みません。形式変更、ファイル不在、読取不能、古いmtime、末尾に観測値がない場合はunknownです。CLIの内部保存形式への依存は限界であり、公式の安定APIとは扱いません。
- unknownでは同一セッション32判断、または累積入力96000文字で予防切替します。これはローカルな通信予算であり、コンテクストのトークン推定でも課金量でもありません。隠れた初期指示・出力・画像の大きさを保証できません。
- 自動圧縮を無効化・置換しません。検証専用セッションで `model_auto_compact_token_limit=14500` に設定し、16907トークンの次のresumeでrolloutの `compacted` 記録と10065への減少を確認しました。同じ実行のexec JSONLには独立した圧縮イベントは出ませんでした。圧縮を全く行わないと仮定したり、exec使用量の減少を圧縮完了と断定したりしません。本番ではCLI/モデルの既定設定を維持します。

公式仕様：[非対話モード](https://learn.chatgpt.com/docs/non-interactive-mode)、[設定リファレンス](https://learn.chatgpt.com/docs/config-file/config-reference)。自動圧縮の閾値は `model_auto_compact_token_limit`、コンテクスト窓は `model_context_window`。圧縮閾値そのものを今回のobserverが取得できるとは主張しません。

## 復旧と操作の重複防止

コンテクスト超過とセッション消失だけを識別し、1判断につき新セッションで1回、未完了ターン全体で最大2回まで復旧します。実CLIの消失エラーは `no rollout found for thread id …` でした。認証・通信・レート/課金制限・一般エラーは上限扱いしません。違うセッションIDが返った場合も裸の新セッションの行動を実行せず、引き継ぎ付きで限定再試行します。

切替意図を新しいCodex起動前に永続化します。途中停止では意図を復元し、旧セッションへ戻さず新規引き継ぎを行います。通常のidle再起動は同一IDをresumeします。thinking中断は未完了発言を保持してUIに明示し、次の村長発言から続けます。回答保存後・idle設定前の停止は完了済みとして復元します。旧版のメモなし会話は最後の完了会話の短い抜粋と原文参照で移行します。旧版の中断には操作事前記録がないため、同じ復旧ターンで変更操作を行いません。

村の変更操作・dispatchの前に `operationLog` へstartedを書き、結果と参照発言IDをcompletedとして保存します。同一ターンの同一操作は保存結果を返すだけです。復旧途中で別形式の操作を提案されても、そのターンに既存操作があれば追加変更を止めます。反映IDを得た後はdeployments get等で照会します。通常通知は既存のメッセージID監査を維持し、復元時には再送しません。報告保存とknownReportsも同じ会話保存に含めます。

**限界:** 外部操作の成功直後・結果保存前に停止するとexactly-onceの成否確定はできません。startedが残る場合は安全側に変更操作を停止します。読取・会話は続けられます。管理者が実状態・`operations.jsonl`・`operationLog`の原要求を照合し、成否を確定する必要があります。自動で成功に書き換えたり、再試行して成否を確かめたりしません。必要な管理修復はバックエンド停止・状態バックアップの上で行い、記録を削除せず状態を`reconciled`として根拠を残します。これは新たな実行許可ではありません。Agent承認・解放は別の村長判断です。

## 診断と検証

`conversation.json` の `diagnostics` だけを読むとlastInputChars、lastMode、memoChars、memoLimit、memoUpdate、context（source/tokens/window）、billingUsage、switchReasonを確認できます。メモ本文、発言全文、CLI stdout/stderr、認証値はこの診断に入りません。`secretary-errors.jsonl` は診断ID・日時・turnId・固定エラー分類だけです。会話・操作記録本体は従来どおり私有状態として保存され、HTTPのファイル配信対象にしません。

Nodeテストは通常resume、メモ置換・不正更新・保存失敗、実測/unknown切替、上限・消失/一般エラー、全未処理報告、旧版、切替中断、回答保存直後、操作後の復旧・二重実行防止を検証します。UIは実HTTP・保存層を使い、Codex境界だけを決定的fixtureへ差し替えた試験を追加しています。既存の画像・会話・報告UI試験も維持します。

```bash
npm ci
npm run check
npm test
VILLAGE_TEST_PORT=5288 \
VILLAGE_TEST_STATE=/専用工房/検証用の新規ディレクトリ \
VILLAGE_TEST_CODEX_BIN="$PWD/tests/fixtures/secretary-codex.mjs" \
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/google-chrome npm run test:ui
npm run build
```

UIの継続試験は明示した独立state/fixture環境で実行します。通常のブラウザ試験環境ではこの追加試験だけをskipし、稼働中の実Codexへ検証発言を送りません。検証用のCodex fixtureを本番へ設定しないでください。
