# 共通依頼と分割

新規依頼は `commonRequests: true`。人間の受付と秘書の委任は同じ Node、入力対応、結果提出の規則を使う。親子関係は取りまとめを表し、作成者を表さない。

終了確認済みの子を同じ担当へ継続する操作は [依頼元Agentによる継続](child-continuation.md) を参照。

## 正本と境界

- Nodeの `createdBy` は作成操作の主体、`recipient` は成果の返却先（human / request）。人間が子依頼を作っても、返却先は親依頼のまま。
- `assignee: null`, `planned: true`, `currentRunId: null` は担当未定・実行前。担当を設定しても開始しない。開始後はplanned=false。
- 依頼は従来どおりrequestGraph、実行の事実はrunModelが正本。本文・出力JSONから状態は推測しない。
- 作業の準備完了条件は共通のready/reconcileGraph。人間宛て・Agent宛てともsubmittedへ進む。子の完了だけで親は完了しない。
- 人間宛ての受入はrequest-deliveryの方針。報告なしなら自動受入、報告ありなら整形完了後に受入。人間に受領操作を追加しない。
- 報告runは同じ依頼に所属して監査できるが、作業のcurrentRunId/submissionsを変更しない。報告失敗は配送の状態として表示し、報告だけを再試行する。
- 補足が報告中に来た場合は報告予約を無効化し、未対応入力として作業を再開する。送信済みの外部操作を巻き戻したことにはしない。

## 操作

`plan` は子依頼の作成、`assignPlan` は開始前の担当変更、`launch` は開始、`discard` は開始前の取り下げ。既存の `delegate` は作成と開始を一つのトランザクションで行う便利操作で、別モデルを作らない。

人間用HTTP `/api/direct/human/requests/{plan,assignPlan,launch,discard}` はhumanRequestId、revision、operationIdと対象を受ける。Agent用HTTP/CLIは親の現在actorRunIdを受け、直接の子に限定する。同じcompose処理を通り、操作主体は入口で決定する。依頼の作成にはparentWorkId/instruction/任意agentId、変更にはworkId/必要なagentIdを指定する。

人間の構成変更は、親の秘書へ未対応入力として保存する。人間が変更した構成を知らずに古い完了申告だけで閉じない。同じoperationIdの再試行は、元の受付内容と照合して重複実行しない。古いrevision、別依頼のrun、開始済みの構成変更は拒否する。保存失敗は子・入力・操作記録をまとめて戻す。

UIは各Agentの「…」→「依頼の構成・分割」。親子関係、担当未定、開始前、進行中、成果提出済み、完了を表示し、開始前だけ担当変更・開始・取り下げを提供する。全村の新しい常設一覧は増やさない。構成は明示的に開いたときに取得する。

## 互換性と対象範囲

既存依頼の実行・対応・通知履歴は変更せず、旧契約で最後まで処理する。新規依頼から共通契約を使う。旧依頼のUIは参照のみで分割は不可。プロトコルの違いは互換経路で扱い、同じ新規依頼の中で混在させない。過去の報告を再送しない。

親子関係の木に限定し、任意の依存グラフ、開始済み依頼の移動、別ツリーへの転送は追加しない。次工程は秘書が先行成果を確認して作成する。工房の一件専有と秘書の複数件保持は既存スケジューラを使い、開始前の計画は実行枠を占有しない。

## 検証と反映

人間/Agentの同じplan・launchシナリオ、秘書→秘書→工房、未割当、古いrevision、他依頼のrun、二重送信、保存失敗、再起動、報告失敗/再試行/補足競合、通知一回を検証する。型・構文・既存回帰・隔離ブラウザも実行する。

反映前に実データをバックアップする。反映後は稼働、既存IDと履歴・通知記録の保持を確認する。新契約の依頼を受け付けた後は古いコードへの単純切替をしない。データは巻き戻さず、受付済みの外部操作と照合して復旧する。

## 差し戻しと再依頼の表示

構成画面では、確定した `replacementId` がある依頼を「差し戻し・再依頼済み」と表示する。人間による取消や未開始計画の破棄は「取り下げ」のまま。置換予約や未確定の申告、指示・成果の文言では判定しない。親の確定済み `handling` と最新提出の結果ID・版を照合し、採用済みなら「承認済み」、提出中なら担当者名付きの確認待ちを表示する。終了した旧依頼に確認待ちを残さない。

「元の依頼」「再依頼へ」で同じ構成画面の該当依頼へ移動できる。見出しは空白・改行を整理した先頭80文字と省略記号に限定する。指示本文は開くと原文のまま末尾まで読める。各依頼の指示本文と各実行の成果・応答はそれぞれ独立して開閉できる。チャットの左右吹き出しとAgentへの矢印遷移は維持する。履歴ページと初期スナップショットには同じ正本から導出した最小限の表示情報を付ける。保存形式や依頼状態は変更せず、移行は不要。欠けた過去本文・参照を文言から復元しない。

実機レビューでは、2回差し戻して3回目を承認した依頼の「依頼の構成・分割」を開き、旧2件の再依頼表示と最終件の承認表示、旧件に確認待ちがないことを確認する。前後リンク、指示・成果の個別開閉、チャットの履歴読み込みと矢印遷移も確認する。通常の取消・計画取り下げは再依頼表示にならないことを確認する。表示確認のために既存依頼の再実行や採否操作は不要。
