# 秘書を「監督役」にする

## 目標の流れ（人間と合意済み）

1. 人間と秘書で方向（目的・範囲・許可）を決める。
2. 秘書がリーダーへ仕事を依頼する。
3. 原則として、終わるまで人間は不要。秘書が次を担う。
   - 定期的に見回る。
   - 止まった仕事を自分で立て直す。
   - リーダーからの仕様の質問に答える。
   - 完了時に成果を確かめ、問題があれば差し戻す。
4. 最後に、秘書が人間へ報告する。何をなぜ判断したかも書く。

人間へ上げるのは、次のどれかに当たるものだけ。
- **元に戻せない**もの。
- **外部に影響する**もの（お金、他人、外部サービス、mainマージ）。
- **人間の価値観でしか決まらない**もの。

それ以外は、合意した方向の範囲で秘書が判断して進める。合意・許可の範囲そのものは広げない。範囲を越える新しい目的は、これまでどおり人間の許可発言を引用した新規依頼になる。

## 既存の仕組みとの関係

| やること | これまで | 今回 |
|---|---|---|
| 依頼・追加修正・取り下げ | `conversations job/followup/amend/withdraw` | 変更なし |
| 成果の確認・差し戻し | `decide accept`、`followup` で継続 | 変更なし（規則で「確かめてから採用、問題は差し戻し」を明記） |
| 止まった仕事の立て直し | `followup` は「旧実行が失敗」で拒否。人間の画面の再試行だけ | **`conversations recover` を追加**（項目2） |
| リーダーの質問 | `requests report kind:question` は秘書へ届くが、「人間へ説明せよ」と案内していた | **秘書が合意から答える案内に変更**（項目3）。答えは既存の `amend` |
| 見回り | なし（配送・期限でしか起きない） | **村が定期的に秘書を起こす**（項目1） |
| 秘書の方針文 | 何でも確認する中継役 | **監督役へ書き直し**（項目4） |

## 1. 見回り（`server/conversation-patrol.mjs`）

- **対象：** 会話に、進行中の仕事が1つ以上あるとき。
  - 進行中とは、実行状態が作業中・配送待ち・受付照合中・保留・要確認（失敗/中断）のどれかであること。
  - 次の場合は対象外：秘書の回答待ち（質問が配送済み）、人間の回答待ち、完了、取り下げ、隔離。秘書がすでに起こされる、または人間待ちのためで、空回りを防ぐ。
- **進展の検知：** 1分ごとに、進行中の仕事の観測可能な状態をまとめた指紋を計算する。
  - 指紋に含めるもの：仕事の各段（子を含む）の状態、現在のrun、runの状態、出力の長さ、記録された事実の数、依頼のrevision。会話の配送・判断の件数も含める。
  - 指紋が変われば進展ありとし、見回りを先送りする。
- **起こす時刻：** 最後の進展（または前回の見回り）から `PATROL_INTERVAL_MS`（12分）たったら起こす。
  - 進展がないまま見回りが続く場合は、間隔を倍にしていく（12→24→48分…、上限4時間）。直せない保留状態で、秘書を何度も空回りさせないため。進展があれば12分に戻す。
- **起こさない時：** 秘書が別の会話runを実行中・配送待ちのとき（その回で状況を見る）、秘書が会話を受け付けられないとき。
- **起こし方：**
  - 会話に「見回り」のrun（`conversationSource:{kind:'program',patrol:true}`）を1つ積む。本文には、進行中の仕事ごとの状態・現在のrun・最後の進展からの経過分数を載せる。
  - requestIdは `conversation-patrol:会話ID:回数` で、重複しない。
  - 状態は会話記録の `patrol` に保存し、再起動後も続きから数える。
- **秘書の対応：**
  - 問題がなければ、何も操作せず短く終える。
  - 止まっていれば、立て直し（項目2）、補足（`amend`/`followup`）、またはリーダーへの確認をする。
  - 人間へ上げる基準に当たるときだけ、`conversations display mode:reply` で人間へ伝える。
- **表示と通知：** 見回りの回は、既定で折りたたみ（途中経過）にし、通知しない（理由 `patrol-quiet`）。明示の `display reply` と、確定した accept/question だけを人間へ届ける。#140 の通知規則と整合する。

## 2. 秘書による立て直し（`conversations recover`）

```
conversations recover JSON {conversationId,actorRunId,operationId,purposeId,instruction}
```

- **対象：** 目的（purposeId）の現在の仕事（最後の継続job）のうち、リーダーの担当分（root）。
- **再試行（retry）：** 最後のrunが失敗・中断・終了済み（`failed`・`interrupted`・`terminated`）のとき。rate_limitも、受付不明が確定して終了扱いになったものも、ここに入る。
- **再開（resume）：** 最後のrunが正常終了したのに、仕事がactiveのまま止まっているとき。ただし、次の場合は再開しない（正常な待機を起こさないため）。
  - 実行中・配送待ちのrunがある。
  - 進行中の子作業がある。
  - 自己再開の予約がある。
  - 秘書・人間の回答待ちである。
- **拒否する場合：** 受付不明のまま（`sent`・`awaiting_input`）、実行中、人間による終了・取り下げ済み、隔離済み、後着の人間入力がある、のどれか。外部操作の二重実行を防ぐため、受付不明を推測で再送しない。
- **許可：** 元の目的の許可（runIdと引用）をそのまま使う。新しい許可は作らない。
- **冪等性：** 会話のoperationIdで受付を記録し、同じoperationIdで同じ内容なら同じ受付を返す。依頼側のrunキー（`retry:`/`resume:`+operationId）でも重複を防ぐ。人間の画面の再試行と同じ `continueLocked` を、同じ保存単位の中で使う。
- **リーダーへの指示文：** 「秘書による立て直し」と明記し、既存の変更・PR・外部操作・子作業を確認して、未完了分だけ進めるよう固定文で伝える。

## 3. リーダー→秘書の質問窓口

- **リーダーの質問：** 仕様の不明点は、推測で大きく進めず、既存の `requests report kind:question` で秘書へ質問し、`respond` して待つ（リーダー規則に追記）。
- **秘書への配送文：** 「リーダーからの質問。合意・方針・Project方針から答えられれば `conversations amend {humanRequestId,instruction:回答}` で答える。人間へ上げる基準に当たるものだけ、`decide decision:question` で人間へ具体的に質問する」に変える。
- **通知：** 秘書が答えた回は、仕事の依頼・訂正だけの回として通知しない（既存の `work-dispatch-only`）。人間へ上げた回（確定したquestion）は通知する。
- **リーダーの再開：** amend の時点で、既存の `conversationWait.answerInputId` の仕組みでリーダーが再開する（変更なし）。

## 4. 秘書の規則とProject方針

- **秘書の規則：** `rules get work`（秘書の会話用方針）を監督役として書き直す。revisionが変わるので、各Agentは次の配送で再取得する（既存の動的規則の契約）。
- **Project方針：** `projects guide ID secretary` の既定方針の置き換え文（`SECRETARY_POLICY`）を同じ趣旨に直す。保存済みのProject方針の本文とrevisionは書き換えない。標準方針と完全に一致する部分だけを置き換え、独自の追記は全文のまま残す（既存の仕組み）。
- **失敗の報告：** 秘書が立て直しや補足で自分で対処した失敗の報告（attention）は、人間へ通知しない（理由 `secretary-handled`）。対処しなかった失敗報告は、従来どおり通知する。人間による終了・取り下げの報告（important-change）は変更しない。

## 変えないこと

- 正式な受付照合、operationIdの冪等性、受付不明を再送しない原則。
- 人間の許可発言を引用しないと新しい目的を始められないこと。
- mainマージ・外部影響のある操作には、人間の明示許可が要ること（規則と方針で明記）。
- 過去の通知・記録。旧データの形式移行はしない（`patrol` は会話記録に任意で付く欄）。

## テスト

- `tests/secretary-supervisor.test.js`
  - 立て直し：再試行と再開、冪等性、拒否条件（受付不明・実行中・余分な引数・回答待ち）、正常な待機中は拒否されること、二重配送しないこと。
  - リーダーの質問に秘書が followup で答えると、リーダーが再開し、通知されないこと。
  - 見回り：進展があると先送りし、待ちが倍に延び、実行中は重ねて起こさず、完了した仕事は対象外になること。通知しないこと、明示replyだけ届くこと。
  - 規則とProject方針の文面（文字数上限1700以内）。
- `tests/conversation-notification.test.js`：秘書が自分で対処した失敗報告は通知しない。
- `tests/browser/secretary-patrol.spec.js`：見回りの回の折りたたみとラベル、明示replyの表示（PC幅・スマホ幅）。
