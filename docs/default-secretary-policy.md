# デフォルトの秘書方針

Project作成時にデフォルト本文を設定します。既存の未設定Projectも起動時に一度だけ初期化します。デフォルトは `server/project-guides.mjs` の `DEFAULT_SECRETARY_POLICY` です。個別指示を優先し、新規作業ブランチで検証・commit・push・PR作成までを基本範囲とします。指定された開発ブランチを分岐元・PR先とし、指定がなければ最新mainを起点とします。同じ作業は未完了の既存PRに追加し、マージ済み・クローズ済みなら新規PRを作成します。mainへの直接実装と無断マージは行いません。

人間から明示的な実装指示があるまで、実装や工房への作業指示を行いません。相談・方針検討・案への同意だけでは、実装指示とみなしません。

方針文書は操作許可の範囲を自動的に増やしません。開発ブランチへのマージ・本番反映には、Project方針や個別指示による許可が必要です。

## 閲覧・編集

秘書の名前からプロフィールを開き、「秘書の方針」の「編集」でMarkdown本文を変更し、「保存」を押します。「再読込」と `projects guide PROJECT_ID` は同じ最新内容を返します。工房Agent・未所属秘書には編集機能を出しません。編集取り消しは未保存の下書きを破棄します。

保存は人間用 `PUT /api/direct/human/projects/:id/guide` に `{revision,content}` を送ります。既存のCookie・Origin・ヘッダによる誤操作防止を使います（Agentに対する認可境界ではありません）。空白のみ、NUL、20000文字超、文字列以外は400、表示時からの変更は409です。削除中・削除済みのProjectは変更できません。競合や通信失敗時は下書きを残し、自動再送・強制上書きしません。本文を控えて編集を取り消し、再読込して必要な変更を反映してください。

## 保存と旧文書の互換性

- 本文と版は村の状態ディレクトリの `direct.json` 内 `projectPolicies[projectId]` に保存します。既存の排他制御・永続化境界・fsync・atomic renameを使い、Project作成と初期設定も一緒に保存します。既知の保存失敗は元の状態へ復元し、永続化結果不明時は既存の書込停止処理に従います。
- 保存済み本文は起動時・閲覧時・デフォルト本文更新時にも再注入しません。
- 旧 `village/projects/index.json` に個別マッピングがあればデフォルトを設定しません。画面で初めて保存するまでは元Markdownを毎回読み、ファイル変更も反映します。画面保存後は村の保存本文を優先し、元文書は変更しません。
- 文書消失・不正なパス・読取不能・破損manifestは「未設定」と推測して置換しません。その場合は取得不可のままにし、文書設定の修復が必要です。
- 版は保存回数と本文SHA-256（旧文書はSHA-256）を含みます。同時保存は1件だけ成功します。旧文書を外部編集する場合、村の保存操作とファイル編集は共通のロックを持たないため、同時編集は避けてください。

## 検証

`tests/project-guides.test.js` は初期化、既存文書、版競合、入力検証、保存失敗の復元、再起動、HTTP誤操作防止を確認します。`tests/browser/project-guides-live.spec.js` は独立した一時状態とサーバーで実際の保存APIを使い、初期設定・編集・競合下書き保持・再読込・再起動後の保持を確認します。Agent名簿のみ画面用の仮データで、Agentは起動しません。
