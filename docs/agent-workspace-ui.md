# Agentワークスペース（2026-11-04）

後続の [会話・起動・送信状態の修正](agent-state-and-chat.md) で左右の会話表示、起動入口、再読み込み時の下書き復元、バックエンド共通の送信可否を追加しました。

利用URL: http://100.87.176.23:5173/agents （VPN内）。`ai-village-direct.service` が稼働する開発ブランチの画面。旧3拠点固定の一覧を置き換える。

## 操作

- **対象 → 全部**: 村長の家の秘書と、全登録工房の稼働Agentを対象にする。
- **対象 → 工房**: 工房・場所を選ぶ。村長の家も同じ選択肢に含む。登録数の上限をUIに固定しない。
- **対象 → Agent**: 工房・場所、続いて特定Agentを選ぶ。
- 上のAgentタブで切り替える。左右矢印キー、Home、Endも利用できる。名前の横に所属場所、状態色を表示する。
- **同時表示**: 1（拡大）、2、4、6、9を選べる。対象数が表示枠数を超えると左右のページボタンで切り替えられる。画面外のAgentタブを選んでもそのページへ移動する。各パネルの拡大ボタンはそのAgentの1枚表示にする。
- 個々の会話領域だけをスクロールする。Agentの切替、絞り込み、分割数変更、サーバーの定期更新でも、入力途中の文章とスクロール位置をAgentごとに保持する。保持はそのブラウザページ内であり、ページを閉じた後の下書き復元は対象外。
- **起動・工房設定**から既存の登録／編集／起動機能を利用する。指示・追加指示・PurpleMuxリンク・終了は各パネル内にある。状態はバックエンドの実際の稼働状態を表示し、待機中には古いツール実行を「現在の作業」として表示しない。

## 終了と履歴

バックエンドが `terminated` と確認したAgentだけを通常表示・選択肢・Agentタブ・会話パネルから除く。`stopping`、`stop_unknown`、接続不明を終了と推測して隠さない。データ削除は行わず、**終了Agentの履歴**から選んで過去の指示・返答・通知結果を読める。終了後に通知のAgentリンクを開いた場合も、通常タブを復活させず履歴ダイアログを開く。

暗い作業画面、コンパクトな上部操作バー、状態色を持つパネルの縁・ヘッダー、タブ切替、拡大、9枠ごとのページ切替を参考にし、AI村の会話UIとして独自実装した。MulmoTerminalのバックエンドは参照・導入していない。接続・実行・永続化・通知はAI村とPurpleMuxの既存基盤を使う。

## 実行識別

前回導入したnative session／input／turn IDとランタイムイベントの仕組みを維持する。UI側で本文を解析したり、モデルに識別子・JSON・終了宣言を出力させたりしない。server／src／scriptsに旧実行マーカー・出力スキーマ指定がないことを再確認した。詳しくは [ランタイム制御](native-runtime-board.md) を参照。

## 検証

- 自動テスト84件成功。ランタイム識別、過去の結果、外部入力の競合、再起動、通信不明、通知などの既存テストを維持。
- ブラウザ自動テスト25件成功、既存条件付き1件skip。13 Agent／4工房＋秘書のデータで、最大9分割、次ページ、3段階絞り込み、タブ切替、独立スクロール、下書き保持、終了未確定の表示継続、終了確定後の除外、履歴、終了Agentへの通知リンクを検証。390px幅でもページ全体の縦横はみ出しなし。
- 実機検証は通常運用の登録データとは別の状態ディレクトリ・localhost:5186で同じコードを起動して実施。E-ryzenはローカル、E-frontierはSSHで操作し、2台を4つの論理工房として登録（物理PCが4台あるという意味ではない）。村長の家を含め計10個の専用Codexを起動して表示を確認。
- 実機のChromeでも9分割／10個目へのページ切替、5場所の選択、3段階絞り込みを確認。両PCで自由文の指示→native turn完了→追加指示→別turn完了を取得し、会話の独立スクロール・下書き保持・対象Agentの終了後の非表示と履歴閲覧を確認。JSエラーなし。
- 10個の検証Agentだけを終了し、すべてremainingOwned: 0を確認。検証前から存在したタブが残っていることも照合。通常運用のAgentは操作していない。
- 通知は検証用バックエンドのみ無効化。通常サービスのNotify設定・トークンは変更しない。今回、実配送を確認したとは扱わない。
